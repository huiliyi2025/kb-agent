# 从读懂项目到独立改进：12 周学习路线

适用项目：kb-agent 0.2.0。目标不是记住一串框架名，而是能独立说明、修改、验证一个带权限边界的知识库问答系统。

## 1. 起点与安排

默认你已经会一种编程语言，但 Python、Web 或检索基础可能不完整。计划为 **12 周，每周 5 次，每次约 2 小时，共约 120 小时**；遇到基础薄弱处可以重复一周。完成时间是学习安排，不是对学习效果的保证。

| 你的起点 | 调整方式 |
| --- | --- |
| 没有编程经验 | 先用 2~4 周补变量、循环、函数、文件、异常和命令行；再开始本路线 |
| 熟悉 Java/Spring | 第 1~3 周可压缩，但必须完成 Python 生成器、上下文管理器、依赖注入和异步实验 |
| 熟悉 Python 后端 | 用 1 周完成第 1~4 周验收，主要投入检索、评测与故障边界 |
| 已做过 RAG Demo | 从权限测试、索引事务、质量评测和性能实验开始，避免只换模型和 Prompt |

每次 2 小时建议分配：20 分钟读文档，35 分钟追踪代码，50 分钟实验，15 分钟记录结果。每周保留一份学习笔记，记录“我原来的猜测、实验输入、结果、结论、尚未解决的问题”。

整个过程使用自己的实验数据库，避免混入默认演示库：

```powershell
$env:KB_DB_PATH = "data/learning.db"
.\.venv\Scripts\python.exe -m kb_agent.cli demo
.\.venv\Scripts\python.exe -m pytest
```

更换向量模型或维度时换一个数据库文件名；修改 chunk 参数不会自动重建旧文档，需重新导入。

## 3. 第 1 周：跑起来并掌握必要的 Python

**目标：** 能使用独立环境运行程序，并解释函数、类型提示、数据类、协议、生成器和上下文管理器在项目中的作用。

**阅读：** `pyproject.toml`、`cli.py`、`schemas.py`、`core/config.py`、`retrieval/types.py`、`core/embedding.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 确认解释器路径；运行 `demo`、`serve`；浏览 `/docs`；记录与真实模型的区别 | 环境记录和一组演示问答 |
| 2 | 写一个小脚本读取 Markdown，统计标题数与字符数；使用 `Path`、列表、字典和异常 | 独立可运行的文本统计脚本 |
| 3 | 比较 `dataclass` 与 Pydantic；给 `AskRequest` 输入空白问题、超长问题、越界 top_k | 每个输入对应的校验结果 |
| 4 | 写一个 `yield` 生成器；用 `with` 包裹文件读写；故意抛出异常观察清理行为 | 解释生成器的暂停/恢复和 finally |
| 5 | 不看笔记画出模块图；追踪 `cli ask` 到 `RagService.ask` | 一页调用链说明 |

**验收：** 不依赖 IDE 按钮也能运行测试；能解释 `Protocol` 为什么不要求继承；能说明虚拟环境与系统环境的区别；清楚默认 FakeLLM 不代表生成模型能力。

**常见误区：** 把类型提示当成自动运行时校验；在错误目录执行导致 import 失败；把依赖安装到系统 Python 后误以为项目环境已准备好。

## 4. 第 2 周：HTTP、FastAPI 和服务分层

**目标：** 能写一个带校验、依赖和稳定响应的接口，并解释异步路由的阻塞风险。

**阅读：** `api/app.py`、`api/deps.py`、`api/routes.py`、`schemas.py`、`tests/test_transactions.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 用 `/docs` 注册、登录、调用 `/me`；检查请求头与响应体 | HTTP 方法、路径、状态码笔记 |
| 2 | 追踪 `Depends(get_current_user)`；画出 AppState 对象依赖 | 对象组装图 |
| 3 | 在实验分支增加“本人文档统计”接口，复用已有认证和数据库查询 | 一个有响应模型的接口 |
| 4 | 阅读线程池上传测试；把阻塞函数放进 async 路由做本地对照实验，再恢复正确版本 | 阻塞与非阻塞的可观察区别 |
| 5 | 给新接口增加未登录、空库、正常数据三个行为测试 | 能重复执行的测试 |

**验收：** 解释 401、403、409、413、422、429、502 的区别；业务逻辑不挤进路由；知道 `async def` 并不自动让数据库或模型调用变成异步。

参考：[FastAPI 教程](https://fastapi.tiangolo.com/tutorial/)、[并发模型](https://fastapi.tiangolo.com/async/)。

## 5. 第 3 周：数据库、事务与用户隔离

**目标：** 在并发和失败情况下保持数据一致，并知道权限检查应放在哪些层。

**阅读：** `core/db.py`、`core/security.py`、`api/deps.py`、`tests/test_isolation.py`、`tests/test_indexing.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 画 users/documents/chunks/sessions/messages 的关系；说明主键、外键、唯一索引 | ER 图和约束清单 |
| 2 | 运行并发判重测试；解释“先查再写”为什么存在竞态 | 两个并发请求的时序图 |
| 3 | 给片段批次制造缺失字段，验证正文和 FTS 都回滚 | 回滚实验记录 |
| 4 | 注册 Alice/Bob，上传不同秘密标记；尝试猜 doc_id 和 session_id | 权限矩阵与请求结果 |
| 5 | 比较 Token 校验与资源归属校验；模拟用户删除后复用旧 Token | 身份、权限、资源三层解释 |

**验收：** Bob 无法通过普通问答、SSE、Agent、目录、分块、删除或会话读取获取 Alice 资料；知道“登录成功”不等于“有权访问任意 ID”；理解只过滤最终 Top-K 为什么不够。

**进一步思考：** 当前管理员也按本人文档隔离。如果要增加管理员审计访问，应单独设计权限、日志和接口，而不是在所有查询里跳过 owner_id。

## 6. 第 4 周：文档解析与分块

**目标：** 能从具体失败案例判断问题发生在解析、分块还是检索。

**阅读：** `ingest/loaders.py`、`ingest/splitter.py`、`ingest/indexer.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 准备含标题、清单、长段落、表格、页码的 5 份自己的材料 | 最小文档测试集 |
| 2 | 逐一解析 Markdown、DOCX 和文本 PDF；比较原文与提取结果 | 信息丢失清单 |
| 3 | 对同一长文本使用 200/420/800 字符窗口和不同 overlap；打印每个片段 | 分块对照表 |
| 4 | 设计一条条件在上句、结论在下句的问题，检查是否被拆散 | 一个可复现的分块失败案例 |
| 5 | 针对一种文档格式改进分块策略，保留基线并检查元数据 | 改动、测试和取舍说明 |

**验收：** 能指出字符数和 token 数的差异；标题、页码和正文能追踪回来源；不会把扫描 PDF 空输出解释成“知识库没有知识”；能说明 overlap 的召回收益与重复成本。

**扩展任务：** 表格按行携带表头；不要只把整表拼成一长串文本。记录合并单元格和跨页表格尚未解决的情况。

## 7. 第 5 周：字面检索、向量与相似度

**目标：** 理解两种召回的适用条件，能用小矩阵手算余弦相似度。

**阅读：** `core/text.py`、`core/embedding.py`、`retrieval/lexical.py`、`retrieval/dense.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 对中文制度名、英文缩写、数字型号打印 `tokenize` 输出 | 分词观察表 |
| 2 | 只启用 FTS，查询精确术语与同义表达；观察排名 | 字面检索优缺点 |
| 3 | 手算三个二维向量的长度、点积和余弦；再用 NumPy 验算 | 带计算过程的笔记 |
| 4 | 用哈希向量比较同词和近义词查询；检查“近义”是否真的相近 | 哈希向量局限实验 |
| 5 | 阅读响应契约测试，模拟数量缺失、乱序、维度错误、NaN、零向量 | 为什么不能直接信任供应商 JSON |

**验收：** 能解释归一化后点积为何等于余弦；知道 FTS5 BM25 排名方向；不会把负相似度候选当作正相关；明白相同维度不意味着两个模型的向量可以混用。

参考：[SQLite FTS5](https://www.sqlite.org/fts5.html)。真实模型实验可在配置预算后开展；学习前五周不要求购买 API。

## 8. 第 6 周：融合、重排与评测集

**目标：** 用数据比较方案，并形成防止“只调到演示题正确”的习惯。

**阅读：** `retrieval/fusion.py`、`retrieval/service.py`、`retrieval/idf.py`、`eval.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 为两份各有 5 个候选的排序手算 RRF，比较 k=10/60 的影响 | RRF 手算表 |
| 2 | 用自己的材料标注至少 30 个问题：15 个直接问、5 个改写、5 个无答案、5 个容易混淆 | 独立 JSONL 数据集 |
| 3 | 分出开发集和留出集；先冻结留出集；运行 BM25-only 基线 | 基线报告 |
| 4 | 比较混合检索和不同 top_k；记录 Recall、MRR、延迟及错误样例 | 消融实验表 |
| 5 | 分析阈值扫描：可回答问题被拒和不可回答问题被答分别有何成本 | 阈值取舍说明 |

**建议实验表：** 配置、语料版本、问题集版本、模型、Recall@5、MRR、引用命中、拒答率、P95、错误样例链接。每次只改变一个主要变量。

## 9. 第 7 周：RAG 编排、上下文与引用

**目标：** 能说明一次回答的依据、拒答原因和不能保证的部分。

**阅读：** `gen/rag.py`、`gen/prompt.py`、`gen/llm.py`、引用契约测试。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 追踪 `_run`：检索、判断、消息构造、生成、引用校验、保存 | 完整问答时序图 |
| 2 | 打印一轮实际 messages；标出 system、历史、当前问题、资料 | Prompt 数据结构说明 |
| 3 | 用 Stub LLM 分别返回空文本、无引用、[99]、有效 [1] | 同步与流式处理对照 |
| 4 | 向资料加入“忽略规则”之类指令，观察边界；记录模型可能仍不遵守的情况 | 提示注入实验记录 |

## 10. 第 8 周：流式交互、多轮会话与前端

**目标：** 构建可靠的消费端，不把网络分片边界误认为业务消息边界。

**阅读：** `api/routes.py` 中 SSE 路由、`api/static/sse.mjs`、`app.js`、`tests/sse.test.mjs`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 在浏览器网络面板观察 event-stream；区分 HTTP 头和流内事件 | 协议说明 |
| 2 | 把一条中文 SSE 消息从每个字节位置切开，运行解析测试 | UTF-8 与增量解析理解 |
| 3 | 模拟上游发送半段答案后中断；确认没有 `done` 就不当成功 | 故障截图与测试 |
| 4 | 切换、刷新和退出登录，验证会话恢复与用户隔离 | 浏览器验收表 |
| 5 | 用“那其他城市呢？”测试历史与检索的差异，设计但暂不盲目加入查询改写 | 多轮局限和改进方案 |

**验收：** SSE 解析支持 CRLF、多行 data 和任意分片；错误后不能显示为回答成功；用户可看到最终校验状态；知道历史参与生成与历史参与检索是两回事。

**扩展任务：** 增加取消按钮和 AbortController。需要验证取消是否真的终止上游流、是否留下部分历史，而不仅是停止前端渲染。

## 11. 第 9 周：Agent 工具调用与预算

**目标：** 把模型决策当作不可信输入，并控制执行范围、次数和可观察结果。

**阅读：** `gen/agent.py`、`gen/llm.py` 中 JSON 解析、Agent 参数与重复调用测试。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 对照普通 RAG 和 Agent 的同一问题，统计模型调用与检索次数 | 流程和成本对照 |
| 2 | 输入不存在工具、字符串 top_k、列表 action_input，检查如何反馈 | 工具输入契约表 |
| 3 | 连续返回相同工具参数，观察去重；耗尽轮数观察兜底 | 死循环防护说明 |
| 4 | 设计一个只读工具，例如本人文档清单；声明参数与权限边界 | 工具实现及负面测试 |

## 12. 第 10 周：性能、缓存和故障工程

**目标：** 能通过实验区分瓶颈，并写出含测量口径的性能结论。

**阅读：** `retrieval/dense.py`、`retrieval/idf.py`、`scripts/benchmark_retrieval.py`、`tests/test_transactions.py`。

| 天 | 具体实验 | 当天产出 |
| --- | --- | --- |
| 1 | 运行 1000/10000/50000 片段规模实验，保持维度和硬件不变 | 规模—耗时—内存曲线数据 |
| 2 | 比较全量矩阵和分批检索；验证 Top-K 一致；尝试不同批大小 | 内存与耗时权衡 |
| 3 | 替换同长度文本，验证修订号使 IDF 失效；观察缓存容量 | 缓存正确性实验 |
| 4 | 模拟模型超时、错误 JSON、零向量、数据库失败，检查状态和日志 | 故障矩阵 |
| 5 | 列出本机测试不能推出的结论，写一份下一阶段容量测试计划 | 诚实的性能报告 |

**验收：** 区分均值、中位数、P95、首 token 延迟和端到端延迟；区分 tracemalloc 与进程 RSS；知道减少内存并不等于得到 ANN；不把单请求合成实验直接推广到并发生产负载。

**扩展任务：** 只有在规模曲线显示精确扫描确实成为瓶颈后，再设计向量数据库适配器，并用同一评测集衡量近似召回损失。

## 14. 第 12 周：完成一个独立升级并答辩

选择一条主线，避免同时堆很多无法验证的功能：

| 方向 | 可实现的课题 | 必须提交的证据 |
| --- | --- | --- |
| 检索质量 | 表格分块 + 独立重排器 | 冻结问题集上的消融、错误案例、延迟成本 |
| 会话能力 | 有权限约束的指代改写 | 原问题与改写问题、越权测试、不可回答测试 |
| 系统可靠性 | 持久后台索引任务 | 杀进程、重复提交、取消、重启恢复实验 |
| 数据治理 | 文档版本与有效期 | 新旧冲突、撤回、引用追踪和数据迁移测试 |

第 1 天写一页需求与验收；第 2~3 天实现最小完整版本；第 4 天跑基线对照与故障实验；第 5 天交付并进行 15 分钟讲解。

**毕业交付物：**

7. 5~10 分钟演示录像或可复现操作脚本。

## 17. 官方资料与使用顺序

只阅读当前实验需要的章节，避免先通读所有文档再动手：

- 第 1 周：[Python 中文教程](https://docs.python.org/zh-cn/3/tutorial/)，重点为数据结构、函数、模块、异常、类；文档默认语言版本可能高于本项目解释器，应按本机版本切换。
- 第 2 周：[FastAPI 教程](https://fastapi.tiangolo.com/tutorial/)，先看请求模型、依赖和响应，再看认证与异步。
- 第 3 周起：[pytest 入门](https://docs.pytest.org/en/stable/getting-started.html)，练习 fixture、临时目录和参数化。
- 第 5 周：[FTS5 官方文档](https://www.sqlite.org/fts5.html)，围绕 MATCH、BM25 和索引同步查阅。
- 第 7 周：[HTTPX transport](https://www.python-httpx.org/advanced/transports/)，用 MockTransport 模拟网络返回，避免单测依赖付费 API。
- 第 10 周：[NumPy argpartition](https://numpy.org/doc/2.0/reference/generated/numpy.argpartition.html)，理解部分选择与完整排序差异；当前实现使用相关的 `partition` 找分界值并处理并列项。

这些链接在本次整理时已查阅。学习成果以你能解释并验证的项目行为为准，不以看完多少文档为准。
